# 基准测试: GDS vs RDMA 4MB 单步 PUT (多轮稳定版)

**日期**: 2026-07-30
**测试环境**: 128 核 Intel Xeon Platinum 8358P, NVIDIA A800 80GB, Mellanox ConnectX-6 100Gbps RoCE v2 (mlx5_2)
**Proxy**: `--num_threads=8` (本次从 4 调至 8)
**数据搬运**: **真实搬运** — GDS 走 cuObj RDMA READ from GPU, RDMA 走 libibverbs RDMA READ from host memory
**测试方法**: 每配置多轮重复（最大 10 轮），取连续 3 轮 ops/s 方差 < 5% 为稳定值；未能稳定者标 `~` 取全样本均值
**bench 参数**: `--size 4M --count 100 --warmup 5`

## 3. 关键发现

### 3.1 Proxy `--num_threads=8` 的影响

| 影响 | 详述 |
|------|------|
| **GDS w/disk 提升** | conc=4 从 255→387 (+52%), conc=8 从 486→744 (+53%) — 更多线程有效重叠了磁盘 I/O 等待 |
| **RDMA 全面下降** | 尤其是 w/disk 场景: conc=32 从 1862→885 (-52%) — 更多线程带来的上下文切换和锁竞争反而拖慢了纯网络路径 |
| **no-disk 两端均下降** | GDS no-disk 和 RDMA no-disk 均比上版低，但 GDS w/disk 受益最多 |

### 3.2 方差分析

| 通路 | 方差特征 |
|------|---------|
| **GDS no-disk** | conc=1/4/16/32 均未稳定，ops/s 波动可达 ±30% |
| **RDMA no-disk** | conc=8/16/32 未稳定，与上版观察一致（RDMA 4MB 方差 40%+） |
| **GDS w/disk** | 低并发稳定，高并发 (16/32) 方差大 |
| **RDMA w/disk** | conc=1 稳定，中高并发部分稳定，但绝对吞吐大幅下降 |

## 5. 结论

1. **Proxy `--num_threads=8` 对 GDS w/disk 有显著正面效果** (+52% @ conc=4, +53% @ conc=8)，磁盘 I/O 等待场景下更多线程可提高并发度
2. **RDMA 全场景下降**，尤其 w/disk 下降 40-52%，推测更多线程的上下文切换和锁竞争对纯网络 + 磁盘混合路径有负面影响
3. **方差仍然是核心问题**：20 组测试中仅 9 组在 10 轮内达到 <5% 稳定，高并发 GDS no-disk 和 RDMA 方差最大
4. **建议**: proxy `--num_threads` 针对 GDS 和 RDMA 可能需要不同最优值，GDS w/disk 宜用 8，RDMA 宜用 4；或者引入自适应线程池
